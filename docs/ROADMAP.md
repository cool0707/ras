# 今後実装する機能（優先度順）

Mac・Linux・Excel の無い Windows で、RAS と VS Code だけでマクロを開発するのに足りないものを、AI エージェントと人間の両方の観点から優先度順に並べる。仕様の節番号は [RAS_Language_Specification.md](RAS_Language_Specification.md) のもの。実装済みのものは README の「実装状況」を参照。

| 優先度 | 意味 |
|---|---|
| P0 | Excel の無い環境で「書く → 動かす → 確かめる」を回すのに欠かせないもの |
| P1 | 無いと手戻りや推測が多くなるもの |
| P2 | 開発体験を大きく良くするもの |
| P3 | あると便利なもの・残っている仕様の実装 |

## P0

P0 の 3 つは実装済み。使い方は README の「Excel なしで動かす・確かめる（CLI）」、残っているものは下の各項目と README の「実装状況」を参照。

### 1. テスト（`ras test`）

仕様は §14.12。`test/*.test.ras` に vitest 形式で書き、ブックの代役で Excel を起動せずに実行する。AI が自分の変更を確かめる手段になり、人間にとっては回帰テストと CI の土台になる。

* 実装の順序の目安: 列挙（§14.12.3、`--list`）→ 実行と `expect`（§14.12.4、§14.12.6 前半）→ ブックの巻き戻し（§14.12.5）→ `--reporter json`・失敗したテストのブック（§14.12.7、§14.12.8）→ 置き換え（§14.12.6 後半）→ エディタ（§14.12.10）→ `--excel`。
* **実装済み:** 列挙、実行と `expect`、ブックの巻き戻し、`--reporter json` / `junit`、失敗したテストのブック、置き換え（`mock*`）、`--watch`、`--ci`、`--bail`。
* **残り:** エディタ（§14.12.10。CodeLens、テスト エクスプローラー、言語サーバーでのテストファイルの型チェックと補完）、`--excel`、テストファイルの並行実行。
* **ランタイム（2 と共通）:** PATH の Node.js（環境変数 `RAS_NODE` で指定もできる）を使い、無ければ VS Code の実行ファイルを `ELECTRON_RUN_AS_NODE` で使う。`ras_book.node` は `ras` と同じフォルダーのもの（配布物に同梱）か、環境変数 `RAS_BOOK_ADDON` のものを使う。VS Code の実行ファイルを使う経路は未確認。

### 2. CLI からの実行（`ras run`）

デバッグ実行（§14.10）を VS Code なしで行う。AI エージェントは CLI でしか作業できないため、テストを書く前の試行錯誤や、テストにしにくい一度きりの確認に要る。

```sh
ras run Report.rebuildReport              # 実行して結果を表示
ras run Report.rebuildReport --json       # 結果を JSON で出力
ras run --list                            # 実行できる関数の一覧
```

* 出力: `debug.print` の行、実行時エラー（VBA のエラー番号・説明・`.ras` の位置）、表示したダイアログ（`msgBox` の内容など）、変更されたセルの差分（3 と同じ形式）、保存したブックのパス（`build/debug/workbooks/`）。
* `build/debug/ras-main.js` は既に関数名を受け取って実行できるので、ビルド・ランタイムの起動・アドオンの指定（`RAS_BOOK_ADDON`）・結果の整形を `ras` がまとめて行う。
* ダイアログの応答はコマンドラインで与えられるようにする（`--msgbox vbYes`、`--inputbox "2026/4"` など。6 と共通）。
* **残り:** 手書き VBA・COM オブジェクトの置き換え（6）、引数のある関数・`@on` のハンドラの起動（15）、実際の Excel に対する実行（10）。

### 3. ブックの中身をテキストで見る・比べる（`ras book dump` / `diff`）

AI は `.xlsx` / `.xlsm` を直接読めないため、シートの構成やセルの内容を推測してコードを書いてしまう。人間にとっても、Excel の無い環境でブックの中身や実行結果を確かめる手段になる。

```sh
ras book dump Book.xlsm                                   # シートの一覧、使用範囲、名前、テーブル
ras book dump Book.xlsm --sheet Sheet1 --range A1:F20     # セルの値・数式・表示形式
ras book dump Book.xlsm --sheet Sheet1 --format csv|json|markdown
ras book diff before.xlsm build/debug/workbooks/Book.xlsm # セルの差分
```

* `dump` の内容: シート（名前・コード名・表示状態・使用範囲）、セル（値・型・数式・表示形式・`Text`）、名前定義、テーブル、入力規則、条件付き書式、結合セル、フィルター。既定では値と数式だけを出し、書式はオプションで出す。
* `diff` はセル単位（値・数式・表示形式）と構造（シートの追加・削除・名前の変更、行・列の挿入・削除の推定）の差分を出す。`ras run` とテストの失敗の表示で同じ形式を使う。
* 読み取りは `crates/ras-workbook`（umya-spreadsheet と GridCraft）を使う。
* 出力の形（行数・列数の上限と出力した範囲の表示、同じ形の数式を 1 つにまとめる）は、AI エージェント向けに実績のある xlflow の `inspect` / `formulas` / `diff` を参考にした。
* **残り:** 書式（フォント・色・罫線）の出力と差分、複数箇所の行・列の挿入・削除の推定、テストの失敗の表示でのセルの差分（今はブックのパスを表示する。`ras book diff` で比べられる）。

## P1

P1 の 5 つは実装済み。残っているものは各項目の「残り」と README の「実装状況」を参照。

### 4. 機械可読の診断とエラーの説明

* **残り:** 診断の「関連する位置」（コンパイラの診断に持たせる必要がある）、ユーザーフォームの検査の結果の JSON 出力。

* `ras check --message-format json`（`build` / `pack` も同じ）: コード、重大度、メッセージ、範囲（ファイル・行・列）、関連する位置、クイックフィックスの編集内容を JSON Lines で出力する。現状、構造化された診断は LSP を動かさないと得られない。
* `ras explain E0412`: エラー・警告の説明、典型的な原因、直し方の例を表示する。診断のメッセージにも `ras explain` を案内する。

### 5. ブックの代役で使えない API の事前警告

代役に無いメンバー（エラー 438）、Excel が必要な操作（エラー 445。手書き VBA、ダイアログ、`OnTime` など）、作れない COM オブジェクト（エラー 429）は、今は実行して初めて分かる。

* 同梱の型定義のメンバーに「代役で使えるか」の情報を持たせる（代役の実装から生成する）。
* `ras check --target stand-in`（または `ras.toml` の設定）で、使えないメンバーの使用箇所を警告する。LSP のクイック情報にも表示する。
* AI の無駄な試行と、人間の「デバッグ実行してみたら途中で止まった」を減らす。
* **残り:** 言語サーバーのクイック情報への表示、`Font` / `Interior` など一覧にないオブジェクトのメンバーと、引数の値によって使えない場合の検査。

### 6. ダイアログ・外部呼び出しの置き換え（デバッグ実行）

テストでは `mockMsgBox` などで置き換えられる（§14.12.6）。デバッグ実行と `ras run` でも、対話のあるマクロを最後まで通せるようにする。

* `launch.json` / `ras run` のオプションで、`msgBox` / `inputBox` / `getOpenFilename` / `getSaveAsFilename` の応答（順番に返す値の並び）を与える。
* `application.run` で呼ぶ手書き VBA と、代役に無い COM オブジェクトは、RAS で書いた代わりの関数・クラスを指定できるようにする（テストの `mockRun` / `mockCreateObject` と同じ仕組み）。
* **残り:** `launch.json` の `answers` を実機の VS Code で確かめる。

### 7. シートの表示

ブックの代役は書式を保持するが描画しないため、人間はプログラムの結果を目で見られない。シートを見られないと人間は開発を進められないため、P1 とする。

* デバッグ実行の一時停止中に、VS Code のパネルでシートをグリッド表示する（値・数式・主な書式・結合セル・フィルター）。ステップ実行で変わったセルを強調する。
* 保存したブック（`build/debug/workbooks/`、テストの失敗したブック）を開いて表示するコマンド。3 の `diff` の結果を色付きで表示する。
* フォームのパネル（§14.10.7）と同じ webview の仕組みを使う。
* 書式から見た目への変換は、xljs のブックの PDF 出力（印刷レイアウトの HTML）を参考にした。
* **残り:** VS Code のパネルを実機で確かめる。条件付き書式・テーブルのスタイル・画像・グラフの描画。テストの失敗したブックをテスト エクスプローラーから開く導線。

### 8. AI 向けの短いドキュメント

仕様書は 2,000 行を超え、AI が毎回読むには長い。

* `AGENTS.md`（プロジェクトのテンプレートにも入れる。`ras init` が作る）: 作業の手順（`ras check` → `ras run` / `ras test` → `ras book diff`）、camelCase の規約（§15.3.1）、VBA との違い、よくある間違い、使えないもの。
* `docs/cheatsheet.md`: 構文の早見表（型、関数、ラムダ、`try`、構造体、デコレータ）と、Excel の典型的な操作の書き方。
* `llms.txt`: 仕様書の節の一覧と要約。
* 早見表のコード例は、自動テストで `ras check` に通している。`ras cheatsheet` でも表示できる。

## P2

### 9. 生成 VBA の構文検査

Excel が無いと VBE のコンパイル エラーを確かめられない。生成した VBA が正しいことは RAS（コンパイラ）の側で保証すべきことであり、利用者の開発の流れを止めるものではないため、P2 とする。生成した `.bas` / `.cls` を VBA の文法で構文解析し直し、32bit（`#If Win64` が偽）と 64bit の両方の条件で、構文・宣言の重複・行の長さ・行継続の数・プロシージャの大きさ（64KB）などの VBA の制限（§13.8）を検査する。

* `ras build` の最後に行い、問題があればコンパイラの不具合として報告する（ユーザーのコードの誤りではないため）。
* 手書きの VBA の取り込み（§14.7.1）の前の検査にも使える。

### 10. Windows の Excel への橋渡し

Mac・Linux で作ったものを本物の Excel で確かめる手段。現状、`ras sync` と「Excelで実行」は Windows でしか使えない。

* Windows の機械で `ras agent` を常駐させ、ネットワーク越しにビルド結果の同期・マクロの実行・テストの実行（`ras test --excel`）・結果のブックの取得を行う。
* Windows と Excel のある self-hosted runner で、`tools/excel-check` と `ras test --excel` を CI として実行する手順とワークフローの例。

### 11. 代役と Excel の互換性の突き合わせ

README の「検証状況」のとおり、代役の計算結果・イベントの順序・コピーが解除される操作・保存したブックの書式とフィルターは、Excel の実機と突き合わせていない。

* 同じ RAS のプログラムを代役と Excel（`--excel`）で実行し、結果のブックを 3 の `diff` で比べるテストの仕組みを `tools/excel-check` に加える。
* メンバーごとの対応状況（対応・一部・未対応、既知の違い）の一覧を生成して公開する。5 の情報と同じものから作る。

### 12. API・型定義を CLI で引く（`ras doc`）

* `ras doc Range.find`: シグネチャ、JSDoc、代役で使えるか（5）、使用例を表示する。
* `ras doc --list Excel.Worksheet`: メンバーの一覧。AI が存在しないメンバーを推測で書くのを防ぐ。
* LSP のクイック情報と同じ内容を CLI で出す。

### 13. ロケール・数値精度の違いの警告

デバッグ実行・テストで結果が VBA と変わりうるもの（§14.10.5）を、LSP の情報として示す。日付の既定の書式・`Format`・`cStr` の日付、`long` が 2^53 を超えうる計算、`decimal` / `currency` の計算、`int | double` を `typeof` で絞り込む箇所など。

## P3

### 14. 入力用ブックの生成

テスト・デバッグ用のブックを Excel なしで作る。

```sh
ras book new test/fixtures/sales.xlsx --sheet Sheet1=data/sales.csv --sheet Sheet2=data/master.csv
```

* CSV / JSON からシートを作り、プロジェクトのブックのシート構成（コード名・シート名）に合わせる。`ras test` の `useWorkbook` でそのまま使える。

### 15. 残っている仕様の実装

README の「実装状況」で未実装・一部としているもののうち、Excel の無い環境での開発に関わるもの。

* `ras typegen` と `vba:` インポート（§15.3、§14.7）: 参照設定のライブラリ（ADODB など）の型。タイプ ライブラリは Windows でしか読めないため、生成した `.d.ras` をリポジトリに置いて共有する運用にする。
* `vba/` の非管理モジュールのブックへの書き戻し（§14.9）。
* ユーザーフォームのキー入力・マウスのイベント（§14.10.7）、`ControlSource`。
* リボン（`@ribbon`、§12.5）。
* デバッグ実行・テストでの `@on` のハンドラ・`@udf` の直接の起動（引数を与えて呼ぶ）。
